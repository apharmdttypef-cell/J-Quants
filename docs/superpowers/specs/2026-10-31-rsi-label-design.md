# RSIラベル追加 設計書

優待一覧(`/yutai`)と詳細(`/yutai/:ticker`)に、RSI(14)に基づく「高め/低め」ラベルを表示する。ユーザー作成の原案(2026-10-29)を、株価のSoftHompo移行後の実装に合わせて改めたもの。

## 背景・目的

- 優待クロスや現物買いのタイミング判断で、株価が短期的に過熱しているか売られ過ぎかをひと目で把握できるようにする。
- RSIは日足終値だけから算出できるため、新たな外部取得はせず、`JQuantsStockPrices`に蓄積済みの終値から自前で計算する。

本アプリは個人用。YAGNIで進める。

## スコープ

**含む**

- RSI(14)の算出・分割検出・ラベル判定の純粋関数(`lambda/shared/rsi-calc.ts`)
- `YutaiRiskPrecomputeBatchFunction`での計算と`JQuantsYutaiMaster`への書き戻し
- `GET /yutai`・`GET /yutai/{ticker}`のレスポンスへの項目追加
- 一覧画面のラベル表示、詳細画面のRSI値・算出基準日の表示

**含まない**

- RSIラベルでの一覧絞り込み(`rsiLabel`クエリパラメータ)。表示が定着してから別途検討する
- ウォッチリスト画面(`/tickers`系)への表示
- RSI以外のテクニカル指標(移動平均乖離率、MACD等)
- 価格データ不足銘柄へのバックフィル(日次蓄積で埋まるのを待つ)

## データソース(実装で確認済み、2026-10-31)

- 入力は`JQuantsStockPrices`の`close`のみ。これは**調整前の終値**である。移行前のJ-Quantsバッチは`C`(調整前終値)を保存しており、SoftHompoも調整前の値しか持たない。移行の前後で同じ基準なので、継ぎ目でラベルが不自然に動くことはない。
- 調整後終値が無いため、株式分割の日に見かけの急落が入る。これは分割検出(後述)で扱う。
- 株価は平日JST 09:30の`PriceBatchFunction`が前営業日分を書く。precompute-batch(JST 18:20)が読む最新終値は前営業日の値になる。

## 計算仕様

RSIはWilderの平滑化方式、期間14(定数`RSI_PERIOD = 14`)で算出し、70以上を「高め」、30以下を「低め」とする。

**算出手順**(終値は日付昇順、直近最大60件を使用)

1. 終値が欠損・非数値のレコードを除外する
2. 分割・併合の検出: 当日終値 ÷ 前日終値 ≤ 0.55(前日比 −45%以下、分割とみなす、定数`RSI_SPLIT_DROP_RATIO = 0.55`)、または ≥ 1 ÷ 0.55(約1.818、前日比 +82%以上、併合とみなす)の日があれば、最後にそれが起きた日より前の終値を捨て、その日以降の終値だけを使う
3. 隣接する終値の差分を取り、上昇分(gain)と下落分の絶対値(loss)に分ける
4. 最初の14差分の単純平均を初期の平均上昇・平均下落とする
5. 15番目以降の差分ごとに、平均 = (前回平均 × 13 + 今回値) ÷ 14 で更新する
6. RS = 平均上昇 ÷ 平均下落、RSI = 100 − 100 ÷ (1 + RS)

**分割・併合検出の根拠**

- 1:2以上の分割では株価が半分以下になり、比は0.5以下になる。
- 東証の値幅制限では、通常の値動きで1日に45%下がることはまず無い(制限値幅は基準値段の概ね30%以下。100円未満の低位株だけがこれを超えうる)。
- 低位株の暴落を分割と誤認しても、RSIが`na`になる期間が延びるだけで、誤った「高め/低め」は出さない。
- 併合(2:1以上)では株価が2倍以上になる。上方向の閾値は下方向の逆数で、値幅制限の上限ではごく低位の株を除き届かない。
- 分割・併合の日は終値が新しい基準で、前日は古い基準なので、その日の終値から系列を始めれば基準が揃う。

**特殊ケース**

- 平均下落が0で平均上昇が正: RSI = 100
- 平均上昇・平均下落ともに0(値動きなし): RSI = 50
- 除外・分割検出後の終値が15件未満: RSIは`null`(分割後は15件そろうまで`na`になる)

**ラベル判定**

| rsiLabel | 条件 | 画面表示 |
| --- | --- | --- |
| `high` | RSI ≥ 70(`RSI_HIGH_THRESHOLD`) | 高め |
| `low` | RSI ≤ 30(`RSI_LOW_THRESHOLD`) | 低め |
| `neutral` | 30 < RSI < 70 | 表示なし |
| `na` | RSIが`null`、または最新終値の日付が古い | 表示なし(詳細では「算出不可」) |

**鮮度チェック**: 最新終値の日付がバッチ実行日(JST)から7暦日(`RSI_MAX_STALENESS_DAYS = 7`)より古い場合は`na`とする。蓄積が止まった銘柄(上場廃止・東証以外のみの上場など)で古いRSIを見せないため。年末年始でも最新終値は12/30で、1/4夕方の実行でも5日前に収まる。

**保存値**: `rsi14`は小数第1位で丸めて保存する。判定は丸め前の値で行う。

## アーキテクチャ

計算は既存の`YutaiRiskPrecomputeBatchFunction`(毎日JST 18:20)に相乗りさせ、APIは書き戻し済みの値を読むだけにする。一覧APIのDynamoDB呼び出しを銘柄数に依存させない既存方針を踏襲する。新規Lambda・テーブル・スケジュールは追加しない。

**処理の流れ**

1. price-batchが`JQuantsStockPrices`に前営業日分を保存(既存)
2. precompute-batchが**全銘柄**について直近60件の価格をQuery(`ScanIndexForward: false`, `Limit: 60`)する。
   - 現在の`latestClose`(`Limit: 1`)は、貸借の`calcRisk`と`calcGeneralMarginOnlyRisk`の中でしか呼ばれず、権利月が無い・区分不明の銘柄では呼ばれない。RSIは全銘柄で出すため、Queryをハンドラーのループ(銘柄ごとに1回)へ移し、その先頭の終値を`calcRisk`等へ渡す。銘柄あたりのQueryは最大1回のまま。
3. 日付昇順に並べ替え、`calcRsi`・`toRsiLabel`で判定
4. `JQuantsYutaiMaster`へ、既存の最大逆日歩などと同じ`UpdateCommand`で書き戻す

**`JQuantsYutaiMaster`に追加する属性**

| 属性 | 型 | 内容 |
| --- | --- | --- |
| `rsi14` | number \| null | RSI(14)、小数第1位 |
| `rsiLabel` | `high` \| `low` \| `neutral` \| `na` | ラベル |
| `rsiAsOf` | string(YYYY-MM-DD) \| null | 算出に使った最新終値の日付 |

**API(`lambda/reference-api/index.ts`)**

- `GET /yutai`: 各要素に`rsiLabel`を追加。`YUTAI_LIST_PROJECTION`にも`rsiLabel`を足す(足し忘れると黙って既定値になる)
- `GET /yutai/{ticker}`: `rsi14`・`rsiLabel`・`rsiAsOf`を追加
- 属性が未設定の旧レコード(バッチ未実行)は`rsiLabel: "na"`、他は`null`として返す

**フロント**

- 一覧(`YutaiListPage`): リスク表示の隣に「RSI高め」「RSI低め」の小バッジ。`neutral`・`na`は何も出さない
- 詳細(`YutaiDetailPage`): 「RSI(14) 72.4(2026-10-28時点)」の形式で値と基準日を表示し、`na`なら「算出不可」。近くに「テクニカル指標は参考値」の注記

| 入力 | 期待値 |

| 70.0 | `high` |

| 30.01 | `neutral` |

**precompute-batch**

- Queryが`Limit: 60`・降順で呼ばれ、昇順に並べ替えてから計算されること
- 最新終値が実行日から8暦日前 → `rsiLabel: "na"`、`rsi14: null`
- 最新終値が7暦日前 → 通常どおり算出
- 既存の`UpdateCommand`に3属性が含まれること
- 価格0件の銘柄でも例外にならず`na`になること
- 権利月が無い・貸借区分が不明の銘柄でもRSIが書かれること
- 価格のQueryが銘柄あたり1回であること(最大逆日歩の終値はそのQueryの最新値を使う)

**reference-api**

- 属性ありのレコード → そのまま返す
- 属性なしの旧レコード → `rsiLabel: "na"`、`rsi14`・`rsiAsOf`は`null`
- 一覧の射影に`rsiLabel`が含まれること

フロントは既存画面と同じく自動テストなし。ローカルで目視確認する。

## 移行・本番検証

- デプロイ後にprecompute-batchを手動invokeし、`rsiLabel`の分布(high/low/neutral/na)をログかテーブルで確認する。
- 直近60営業日に分割・併合があった銘柄を探し、`na`または分割後のみで計算されていることを確認する。
- 証券会社チャートとの突き合わせの代わりに、テーブルの終値から本番コードとは別の簡単なスクリプトでRSIを計算し直し、数銘柄が一致することを確かめる(ユーザー決定、2026-10-31)。

## 未決事項・リスク

- **期間14の固定**: 証券会社によっては9日を既定にしている。まずは14で固定し、要望が出たら定数を変える
- **価格データの欠損日**: price-batch失敗で抜けた日は、前後の終値の差分として1日分に畳み込まれる。株価バッチは直近7日分を毎回取り直し、2日連続の失敗はアラームで通知されるので、通常は翌朝までに埋まる
- **第三者表示**: SoftHompo由来の株価から算出した派生データ。本アプリは個人利用に限る方針のまま
