# 予算内で買える優待銘柄ページ(`/yutai/budget`) 設計

GitHub issue #3 の設計。issue本文から、実装と実データに合わせて変えた点は「issueからの変更点」にまとめる。

## 背景

- 優待クロスの銘柄選定時、手元資金で何が取れるかを一覧から目視・手計算している。
- 必要株数が100株でない銘柄(例: 第一興商 200株)があり、株価だけでは必要資金を判断できない。

## 実データ(2026-11-18、`JQuantsYutaiMaster` 1,724銘柄)

| 項目 | 件数・値 |
|---|---|
| `requiredInvestment`(終値 × 補正後の必要株数)がある | 1,602 |
| `requiredInvestment`がnull(終値なし) | 122(全件`minInvestment`あり) |
| 必要株数 ≠ 単元株数 | 569(いずれも`requiredInvestment`は必要株数で計算済み) |
| 第一興商(7458) | `requiredShares=200`、終値1,844円、`requiredInvestment=368,800`、`minInvestment=366,400` |
| `minInvestment`の株数基準 | 必要株数≠単元株数の569件中554件が必要株数ベースの金額に近い |
| 権利月が複数ある銘柄 | 566(2回557、3回3、4回6) |

→ 必要資金は事前計算済みの`requiredInvestment`をそのまま使える。`minInvestment`はフォールバックとして妥当。

## issueからの変更点

| issue | 変更後 | 理由 |
|---|---|---|
| `GET /yutai` | `GET /yutai/forecast`(優待一覧が使う既存API) | `GET /yutai`は存在しない |
| 必要資金を`JQuantsYutaiMaster`に追加 | 追加不要。既存の`requiredInvestment`を使う | precomputeバッチが既に書いている |
| `riskStatus`列 | `forecast.forecastStatus`(一覧の「判定」列) | `riskStatus`は廃止済み(precomputeが`REMOVE`している) |
| 権利確定月の絞り込み | `rightsMonths`で判定 | 次回権利日(`rightsDate`)だけだと、3月・9月銘柄を11月時点で「9月」に選べない |

## 1. API(`lambda/reference-api/index.ts`)

`GET /yutai/forecast`の各要素に次の2項目を足す。読み取りのみで、テーブル・バッチは変えない。

- `minInvestment: number | null` — kabuyutai一覧の必要投資金額。
- `rightsMonths: number[]` — 権利確定月(1〜12)。

`YUTAI_LIST_PROJECTION`に`minInvestment`を足し(`rightsMonths`は既に読んでいる)、`YutaiMasterRow`と
レスポンスに載せる。フロントの`YutaiForecastListItem`型にも同じ2項目を足す。

既存の優待一覧(`/yutai`)の表示は変えない。

## 2. 判定ロジック(`frontend/src/lib/yutai-budget.ts`、純粋関数)

### 株数(複数単元の購入)

100株に限らず、200株・300株…と単元単位で株数を選んで買えるようにする。

実データ(2026-11-18): `unitShares`は全1,724銘柄が100。`requiredShares`が単元の倍数でない銘柄が30
(1株25件、50・75・150・334・590株が各1件)、`requiredShares`がnullが92。

```
unit      = unitShares
minShares = ceil((requiredShares ?? unitShares) / unit) × unit   // 1株以上 → 100株、150株以上 → 200株
株数      = minShares, minShares + unit, minShares + 2·unit, …     // 下限はminShares、上限なし
```

- 株数は購入予定(カート)の各行の「−」「＋」で単元ずつ増減する。カートに入れたときの初期値はminShares。
- 銘柄一覧の株数・必要資金・利回りはminSharesで固定し、カートの株数には連動させない
  (連動させると、必要資金で並べているときに株数を変えるたびに行が動いてしまうため)。
- 株数を増やしても、優待価値は必要株数の段階の値のまま表示する(一覧APIは`benefitGroups`を返さないため、
  上の段階の価値への切り替えはスコープ外)。株数がminSharesより多いときは「優待の対象は◯株以上」と添える。

### 1株あたり価格と必要資金

```
pricePerShare(item) =
  closePrice が数値           → { price: closePrice, source: 'close' }
  そうでなく minInvestment が数値 → { price: minInvestment ÷ minShares, source: 'minInvestment' }
  どちらも無い                → null(判定不能)
必要資金 = pricePerShare × 株数
```

- `minInvestment`は必要株数ベースの金額なので、minSharesで割って1株あたりの推定値にする(注記を出す)。
- 株数がminSharesのとき、必要資金は`requiredInvestment`(= 終値 × 必要株数)と一致する
  (必要株数が単元の倍数でない30件は、切り上げた株数の分だけ`requiredInvestment`より大きい)。
- 現物買い分のみ。信用売り側の委託保証金・手数料・貸株料・逆日歩は含めない。
- 判定不能の銘柄(現状0件)は一覧の末尾に「必要資金不明」として出し、選択不可にする。

### 権利月

- `matchesMonth(item, month)` = `item.rightsMonths`に`month`を含む。
- 既定の月 `defaultBudgetMonth(today, calendar)`: 当月の月末権利の権利付き最終日(`rightsDateForMonth(..., null)`)が
  今日以降なら当月、過ぎていれば翌月(12月の翌月は1月)。月末以外(20日・15日)の権利日は既定月の決定には使わない。

### 予算判定

```
cart      = 追加した順の [{ ticker, shares }]
remaining = cash − Σ(cart の 1株価格 × shares)
一覧の各銘柄の状態(一覧の必要資金 = 1株価格 × minShares):
  inCart        … カートに追加済み(「追加済み」表示。一覧からは再追加できない)
  affordable    … 未追加で 必要資金 ≦ remaining(クリックでカートに追加)
  unaffordable  … 未追加で 必要資金 > remaining。shortfall = 必要資金 − remaining(「あと◯円」)。追加できない
  unknown       … 必要資金不明(追加できない)
```

- 判定は `必要資金 ≦ 残り予算`(等しい場合は買える)。
- カートの「＋」は `1株価格 × unit ≦ remaining` のときだけ押せる(保有現金が未入力なら常に押せる)。「−」は株数がminSharesなら押せない。
- カートから外すと、その銘柄は一覧で再び追加できる。
- `remaining`が負になる状態(カートに入れた後に保有現金を減らした等)も許し、残り予算を赤字で表示する。カートの中身は自動で外さない。
- カートは画面内stateのみ。権利確定月を切り替えるとカートを空にする(モック時点の案)。
- 保有現金が未入力・0以下・数値でないときは判定しない(全件を必要資金つきで出すだけ)。

### 並び替え

- 必要資金(昇順既定) / 優待価値 / 優待価値 ÷ 必要資金(利回り)。
- 優待価値がnullの銘柄は、優待価値・利回りの並び替えでは昇順・降順とも末尾。

## 3. 画面(`frontend/src/pages/YutaiBudgetPage.tsx`)

### ルート

- `/yutai/budget`を`main.tsx`に追加。`yutai/:ticker`より静的パスが優先されるので衝突しない。
- `/yutai`(優待一覧)の上部に「予算から探す」リンクを置く。

### 入力

- 保有現金(円、整数)と権利確定月(1〜12のセレクト)。
- 値はクエリパラメータ(`?cash=1000000&month=12`)にのみ持つ。サーバーには保存しない。
- 選択した銘柄は画面内stateのみ(リロードで消える)。

### 表示

画面は上から「入力」→「購入予定(カート)」→「銘柄一覧」の順。

**購入予定(カート)** — 入力と銘柄一覧の間に置く。
- 見出し行: 銘柄数 / 保有現金 / 合計必要資金 / 残り予算(最も大きく表示)。
- 資金不足(`remaining < 0`)のときは、カートの枠と見出し行を赤にし、見出しの下に
  「資金が◯円不足しています。株数を減らすか、銘柄を外してください。」を`role="alert"`で表示する。
  (カート内では＋が残り予算を超えないので、不足になるのは保有現金を後から減らしたとき。)
- 行(追加した順): 銘柄(コード・社名、詳細ページへのリンク)、優待内容、優待価値、株数(−/＋)、必要資金(1株価格を併記)、判定、「外す」ボタン。
  - minSharesより多いときは「優待は◯株以上」を添える。
  - 1株価格が`minInvestment`由来なら「※終値なし・推定」を添える。
- 空のときは「下の銘柄一覧で銘柄をクリックすると、ここに追加されます」と表示する。

**銘柄一覧**
- 行全体がボタンで、クリック(またはEnter/Space)でカートに追加する。先頭列に「＋ 追加」「追加済み」「予算超過」を表示する。
  行はボタンなので、詳細ページへのリンクは一覧には置かず、カート側に置く。
- 列: 追加状態、銘柄、優待内容、優待価値、必要株数(minShares)、必要資金(minShares分)、利回り(優待価値 ÷ 必要資金)、判定(`forecastStatus`)、最大逆日歩(`maxGyakuhibu`、参考表示)。
  - 1株価格が`minInvestment`由来なら「※終値なし・kabuyutaiの必要投資金額」の注記を付ける。
  - 最大逆日歩は必要株数ベース(参考表示)。
- 既定は「追加済み + 残り予算で買える銘柄」だけを表示する。
- トグル「予算超過の銘柄も表示」をオンにすると、買えない銘柄もグレーアウトして「あと◯円」を添えて表示する。
  カートに入れて残り予算が減り買えなくなった銘柄も同じ扱い(オフなら隠れる)。
- 一覧の並び順はカートの操作で変わらない(必要資金・利回りがminShares固定のため)。
- 一覧データは優待一覧と同じ`fetchYutaiForecastList()`(フィルタなし)で取得し、月の絞り込みはフロントで行う。

## スコープ外(issueどおり)

- 信用売り側の委託保証金の算入
- 売買手数料・貸株料・逆日歩の必要資金への算入(逆日歩は参考表示のみ)
- 予算内での最適な組み合わせの自動提案(ナップサック)
- ユーザーごとの保有現金・選択銘柄の保存

## テスト

- `test/yutai-budget.test.ts`(ルートのjestでフロントの純関数を検証。`return-path.test.ts`と同じ方式)
  - 1株価格: `closePrice`優先、無ければ`minInvestment ÷ minShares`(source付き)、両方無ければnull
  - minShares: 必要株数200 → 200、1 → 100、150 → 200、null → unitShares
  - 200株銘柄は初期状態で200株分の必要資金で判定される
  - カートの株数を＋すると合計必要資金・残り予算が変わり、一覧の必要資金・並び順は変わらない。＋/−の押せる条件(上限・下限)
  - 境界: 必要資金 = 残り予算 は買える、1円超過は買えず shortfall=1
  - カートに追加すると残り予算が減り、未追加の銘柄が unaffordable に変わる。追加済みは inCart。外すと元に戻る
  - 同じ銘柄は二重に追加されない
  - 権利月: 複数月銘柄がどの月でも一致する
  - 既定月: 月末の権利付き最終日の当日は当月、翌日は翌月、12月→1月
  - 並び替え: 優待価値nullが末尾
- `test/reference-api.test.ts`: `GET /yutai/forecast`が`minInvestment`・`rightsMonths`を返す(欠損時はnull・[])
