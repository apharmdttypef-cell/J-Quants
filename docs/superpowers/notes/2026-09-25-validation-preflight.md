## 1. 対象銘柄数

`JQuantsYutaiMaster`の`rightsMonths`に9を含む銘柄: **467件**

このうちJ-Quants `/equities/master`の`MrgnNm`(貸借区分)が`貸借`のもの(=貸借取引の対象銘柄、逆日歩が発生しうる銘柄)に絞ると:

**303件**

内訳:
- `貸借`: 303件 ← 検証母集団
- それ以外(`信用`のみ・`その他`): 151件(逆日歩が原理的に発生しないため除外)
- 一覧に見当たらない: 13件(上場廃止・銘柄コード変更等の可能性、要個別確認)

`JQuantsYutaiMaster`自体の`riskStatus`フィールドは「優待価値と最大逆日歩の比較」であり、貸借区分とは無関係(`value === null`かどうかで決まる)なので、これを貸借判定に使うのは誤り。今回`MrgnNm`で判定し直した。

## 2. 速報と確報の区別 — 【重要: 設計の前提が崩れている可能性】

実際に`lambda/gyakuhibu-history-batch/taisyaku-client.ts`の`fetchTaisyakuCsv`を使って9024のCSVを取得し確認した(調査時刻: **2026-09-24 23:09 JST**、日証金の公表サイクル「当日18時半過ぎ速報」から4時間半以上経過した時点)。

9/24申込分の行:

```
"9024",...,"20260924","東証","貸借","8000","500","63000","200","4700","207100","-144100","3551.00","","1","","14.40","0.00","","","","",""
```

品貸料率(品貸日数分/円)・品貸料率(年率換算)・応札ランクの3列が**すべて空欄**。差引残高は`-144100`(貸株が融資を14万株超過)なので、本来なら品貸料率が発生してもおかしくない状況にもかかわらず空欄のまま。

一方、過去の確報済み行(9/18等)には同じ列に実値(`0.60`, `2.01`, `F`等)が入っている。

**解釈**: 23時台の時点で当日分がまだ空欄ということは、taisyaku.jpのこの詳細ページ/CSV経路には**同日夜の速報値は一切載らない**可能性が高い。日証金公表サイクルの「18時半過ぎ速報」は別の情報源(日証金の別サイト・PDF・リアルタイム配信等)を指しているのではないか。今回のCSV経由では、確報(翌営業日)になって初めて値が入る、という単純な1系統のデータしか観測できていない。

**設計への影響**: 設計書のスナップショットAは「`final`=9/24確報(正式)、`prelim`=9/25速報(参考)」という2バリアントを前提にしているが、**`prelim`側のデータソースが実在するか未確認**。9/25(金)日中のリハーサル実行で、9/24分の確報が本当に反映されているか、および9/25分の同日中の値がどうなるかを実際に確認する必要がある。もし同日速報が本当に取得不可能なら、Bバリアントの「9/25確報(15:00時点で出ていれば)」も同様に出ない可能性が高く、**2スナップショット design はA(確報のみ・翌営業日扱い)に実質1本化する再設計が必要**かもしれない。

→ **ユーザー確認が必要**な項目としてこのまま報告する。

## 3. 全対象銘柄の取得所要時間の見積り

実測(本番と同じ`fetchTaisyakuCsv`関数を5銘柄で実行、間隔1000ms):

|---|---|
| 9024 | 344ms |
| 7203 | 154ms |
| 9418 | 153ms |

平均フェッチ時間: **208ms**。1銘柄あたり合計(フェッチ+待機1000ms) ≈ **1.2秒**。

303銘柄での推定合計時間: **約6.1分**

Lambdaの15分制限に対して十分な余裕(約60%の余白)があり、**Step Functions Map等への分割は不要**と判断する。単一Lambda呼び出しで問題ない。

## 4. 検索ページでの一括取得可否

`https://www.taisyaku.jp/app/stock/search`にアクセスすると`https://www.taisyaku.jp/app/stock`へ302リダイレクトされ、遷移先は「銘柄検索」というタイトルの**銘柄コード単位の検索フォーム**だった。市場全体・日付指定での一括CSV出力に相当するページは見当たらない。

既存の`fetchTaisyakuCsv`実装(銘柄詳細ページ→検索POST→CSV取得、いずれも`/app/stock/detail/{ticker}/...`というticker単位のURL)が示す通り、**taisyaku.jpは銘柄単位のセッション+CSRFトークンに紐づく設計**であり、複数銘柄の一括取得手段は存在しないと判断する。

## 5. 9/25終値の反映タイミング

`PriceBatchFunction`実行ログ(直近3日分)より、実行時刻はJST 18:00固定、所要時間は185〜198秒(約3.1〜3.3分)。18:03〜18:04 JST頃には完了しており、20:00 JSTのスナップショット取得時点では**十分な余裕(約2時間)**で9/25終値が`JQuantsStockPrices`に反映されている見込み。
