## つまずいた点(次回のために)

### 1. Step Functions が `Items` を受け付けない

`cdk deploy` の1回目が失敗してロールバックした。

> Invalid State Machine Definition: 'SCHEMA_VALIDATION_FAILED: The QueryLanguage is set to
> 'JSONPath', but field 'Items' is only supported for the 'JSONata' QueryLanguage'

`ProvideItems.jsonArray()` は `Items` フィールドを生成するが、これは JSONata 専用。既定の
JSONPath では `Pass` でリストを注入して `ItemsPath` で参照する必要がある。

**CDK の API が存在することと、サービスが受け付けることは別物**だった。`tsc`・`synth`・
CDK のユニットテストはすべて壊れた定義のまま通っており、デプロイして初めて分かった。
テストに `expect(map.Items).toBeUndefined()` を足して、戻したら落ちるようにしてある。

### 2. 継続保有条件の書き方が1種類ではない(最重要)

手順4のゲートで `badge-mismatch` が14件出て停止した。調べると**バッジの方が正しく、解析が
誤っていた**。kabuyutai.com は少なくとも4通りの書き方をする:

| 書き方 | 例 |
|---|---|
| `【株式継続保有期間3年以上】` | 当初から対応 |
| `【株式継続保有期6か月以上】` | カメイ(8037)。「間」が脱字 |
| `【2年連続で100株以上を保有】` | NTT(9432) |
| `【通常優待の取得条件を3年連続で満たす】` | 三井不動産(8801) |

リテラル「継続保有期間」を要求していたため後ろ3つを落とし、`holdingKind` が none/bonus に
なり `crossEligible` が `ok` になっていた。つまり**1回のクロスでは取れない銘柄を「取れる」と
表示する**、最も避けたい向きの誤り。修正後、危険側は 8件 → 5件 に減った。

残る5件は正規表現では到達できない:

- **学研ホールディングス(9470)** — 条件が `stit` 見出しではなく本文の散文
  (「2026年9月末の株主名簿に新たに記載され、かつ100株以上保有している」)
- **DAIKO XTECH(8023)** — 100株→1,000円(条件なし)+ 3年以上→2,000円 は正当な長期優遇構造で、
  解析は妥当。サイトのバッジが粗いと考えられる
- ケイブ(3760)、Orchestra Holdings(6533)、岡三証券グループ(8609)も同系統

**5件すべて `badge-mismatch` が付くので画面には「不明」と表示される。** 誤って「可」と出る
銘柄は0。保存値 `crossEligible` は `ok` のままなのでサーバ側の「可」絞り込みにはヒットする
(既知の残課題)。

標本調査: `holdingKind=none` と判定された786件から45件を抽出して実ページを検証したところ、
条件の取りこぼしは**0件**だった。警告が付いていない銘柄は信頼してよい。

### 3. CloudFormation の論理IDはハッシュ接尾辞込み

計画が書いていた `describe-stack-resource --logical-resource-id YutaiMasterSyncBatchFunction`
は ValidationError になる。実際は `YutaiMasterSyncBatchFunction6B55029A`。接尾辞はデプロイで
変わりうるので、前方一致で引く形に計画を直した。

### 4. AWS CLI がこの環境で日本語を出力できない

`'cp932' codec can't encode character` で落ちる。会社名など日本語を含むデータを扱うときは
CLI ではなく Node の SDK から直接読み、UTF-8 でファイルに書いて確認した。

## 残っている課題

1. **絞り込みの既定期間が狭い。** 権利日の既定が当月なので、10月に開くと10月が権利月の銘柄
   しか出ない。ノジマ(権利月3月・9月)は9月分が終わっているため次回が 2027-03-29 になり、
   2026年いっぱいの範囲を指定しても出てこない。優待クロスは数ヶ月先を仕込むものなので、
   既定を「今日から3〜6ヶ月先」にするか、年内の全権利日で絞り込めるようにしたい。
   利用者も「分かりにくい」と確認済み。
2. `crossEligible` が `ok` のまま表示だけ「不明」の5件は、サーバ側の絞り込みと表示が
   食い違う。表示に合わせて絞り込むか、保存値を `unknown` にするかの判断が要る。
3. 投資法人(REIT)の個別ページは株数段階表を持たないため `no-groups` になる。口数単位の
   別構造として扱うかどうか未検討。
