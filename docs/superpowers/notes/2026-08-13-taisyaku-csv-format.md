# taisyaku.jp CSV取得方式の調査結果

ユーザーが実際にブラウザで `https://www.taisyaku.jp/app/stock/search`(銘柄コード7203で検索)を操作した際のHARファイルを解析して判明した内容。

## 確認できたこと

### 1. 検索フォーム(セッション必須・CSRF保護あり)

`POST https://www.taisyaku.jp/app/stock/search#search-result`(`method="post"`)

主なフィールド:
- `csrf_test_name`: hidden、CSRFトークン(ページ読み込みのたびに変わる。事前に対象ページをGETしてHTMLから取得する必要がある)
- `mgrCd[]`: 銘柄コード(例 `7203`)
- `mgrMei`: 銘柄名(任意)
- `mkYmd`: 基準日/申込日。フォーマット `"YYYY / MM / DD"`(スラッシュの前後に半角スペース)。デフォルトは当日
- `kjnYmdFrom` / `kjnYmdTo`: 期間(From/To)。今回のキャプチャでは未入力だったが、フィールド自体は存在する
- その他多数のチェックボックス(`trjoKbn*`, `tiskKbn*`, `signKbn*`, `tjtOstRank*` 等、取引所区分・規制区分・応札ランクなどの絞り込み条件。未チェックならPOSTボディに含めなくてよい)

セッションCookieが必要(このHARでは当該リクエスト自体にはSet-Cookieが無かったが、直前に`/app/stock`から遷移しており、そこで発行された前提と考えられる)。

### 2. 検索結果ページ = 「基準日1日分のスナップショット」であり、時系列ではない

検索結果ページに明記されている注記(原文まま):
> 銘柄名をクリックすることで選択した銘柄の詳細情報画面に遷移し、選択銘柄の貸借残高、品貸料率、制限措置といった情報を**時系列**で確認することができます。

つまり `POST /app/stock/search` の結果ページは「`mkYmd`時点でのスナップショット」(このキャプチャでは「検索結果 2件」= 7203の2市場区分分)であり、**過去の日次推移(実績逆日歩の履歴)を取得するには銘柄詳細ページに遷移する必要がある**。

検索結果ページの「選択された条件」表示は `申込日：2026 / 08 / 13` `品貸日数：1` のみで、`kjnYmdFrom`/`kjnYmdTo`は今回未使用だったため表示されていない(期間指定機能自体はある可能性が高いが、今回のキャプチャでは検証できていない)。

### 3. 銘柄詳細ページのURL(推定、要検証)

検索結果内の「お気に入り」チェックボックスのid属性から、対象銘柄のURLスラッグが `7203-01` `7203-03`(銘柄コード+市場区分)であることが分かった。以前のWebFetch調査で確認していた `https://www.taisyaku.jp/app/stock/detail/3320-01` というURLパターンと一致するため、詳細ページは **`https://www.taisyaku.jp/app/stock/detail/{code}-{marketCode}`** と推定される(`marketCode`は`01`=東証等、`03`=別市場と推定。要検証)。

### 4. CSVリンクの実体

検索結果ページのCSVボタンは:
```html
<a href="csv" download="" class="button-list__item button-list__item--download" aria-label="CSVダウンロード">CSV</a>
```
**相対パス`"csv"`**であり、クエリパラメータは無い。現在のページURL(`/app/stock/search`)を基準に解決すると `https://www.taisyaku.jp/app/stock/csv` になる(標準的な相対URL解決規則)。`download`属性付きの素のリンクなので、JS処理ではなくブラウザの通常のGETダウンロード。**クエリパラメータで日付範囲を渡す方式ではなく、直前のPOST検索で確立したサーバー側セッション状態(検索条件)をそのままCSV化する方式**と考えられる。銘柄詳細ページのCSVリンクも同様の構造(相対`"csv"`)である可能性が高い(要検証)。

### 5. 品貸料率の値についての重要な仕様(検索結果ページの脚注、原文まま)

> 品貸料率（円）は、品貸日数分の料率となります（1日あたりの料率は品貸日数で割り戻してください）。
> 品貸料率（年率換算）：１日あたり品貸料率÷貸借値段×365×100

**「品貸料率(円)」列はその適用期間(品貸日数)の合計額であり、1日あたりの単価ではない。** 1日あたりに換算するには「品貸日数」で割る必要がある。Task 6の実装(`parseTaisyakuCsv`)はこの前提で再検討が必要(CSVの各行が「1日分の料率」なのか「品貸日数分の合計額」なのかは、実際の詳細ページCSVを見て確認する)。

制限措置アイコンの意味: 注=注意喚起、制=申込制限措置、停=申込停止措置、4=最高料率4倍の臨時措置、10=最高料率10倍の臨時措置、特=最低料率引き上げの特別措置。

### 6. 検索結果ページのテーブル列(HTML、CSVも概ね同じ列と推定)

銘柄コード / 市場区分 / 基準日 / 制限措置等 / 融資残高（株） / 貸株残高（株） / 差引残高（株） / 最高料率（円） / 品貸料率（円） / 品貸料率（年率換算/%） / 応札ランク / お気に入り / 銘柄名 / 貸借区分 / 最低料率（円）

## 追記(2回目のHAR: 銘柄詳細ページ `/app/stock/detail/7203-01` を実際にキャプチャ)

1回目で不明だった「詳細情報画面」の実体が、2回目のHARキャプチャ(ページ読み込みのみ、CSVクリック自体は含まれていないがHTMLから確定情報が得られた)で判明した。

### 確定: 詳細画面のURLと検索フォーム

- 画面URL: `https://www.taisyaku.jp/app/stock/detail/{code}-{trjoKbn}`(例 `7203-01`。`01`=東証と推定、`trjoKbn`ラジオボタンの値と対応)
- 期間変更フォーム: `POST https://www.taisyaku.jp/app/stock/detail/{code}/search`(例 `/app/stock/detail/7203/search`)、`method="post"`、`accept-charset="utf-8"`
- フォームフィールド:
  - `csrf_test_name`: hidden、CSRFトークン(ページ読み込みごとに変わる)
  - `orgMgrCd`: 銘柄コード(例 `7203`)
  - `orgMgrMei`: 銘柄名(例 `トヨタ自動車`)
  - `sort` / `page` / `fsort` / `fpage`: hidden、ソート・ページング状態(空でよい)
  - `mkYmdFrom` / `mkYmdTo`: 期間の開始/終了。フォーマット `"YYYY / MM / DD"`(スラッシュ前後半角スペース)。デフォルトは直近7日相当(観測値: `2026 / 08 / 05` 〜 `2026 / 08 / 14`)
  - `kjnYmdDays`: ラジオ(`7`=直近7日, `2`=直近2日, `""`=未選択)。クイック選択用、`mkYmdFrom`/`mkYmdTo`と併用可能と推定
  - `trjoKbn`: ラジオ、市場区分。`01`=東証(toushou、デフォルト)、`03`=名証(meishou)、`06`=福証(fukushou)、`07`=札証(sasshou)
- 画面注記(原文): 「※８営業日以上のデータを指定する場合、CSVデータでご確認ください。」→ 8営業日未満は画面表示のみ、8営業日以上はCSVダウンロードが必要という仕様を裏付け

### 確定: CSVリンク

`<a href="7203/csv" download="">` — 相対パス。現在ページURL `/app/stock/detail/7203-01` を基準に解決すると **`https://www.taisyaku.jp/app/stock/detail/7203/csv`**。検索フォームのaction(`/app/stock/detail/7203/search`)と同じ`{code}/`配下のパターンで一貫している。クエリパラメータなし、直前の期間指定検索のセッション状態をCSV化する方式(1回目の調査と同じ結論)。

### 確定: 画面の時系列テーブル構造(CSVも同じ列と推定)

列(日付ごとに1列、行=属性という縦持ちのHTML表。CSVは通常の横持ち=行が日付になっている可能性が高いが要検証):

`申込日` / `貸借区分` / `貸借取引残高(株・口)`[`融資`(`新規`/`返済`/`残高`)、`貸株`(`新規`/`返済`/`残高`)] / `差引残高` / `貸借値段(円)` / **`品貸料率(品貸日数分/円)`** / **`品貸日数`** / `品貸料率(年率換算/％)` / **`最高料率(品貸日数分/円)`** / `最低料率(品貸日数分/円)` / `応札ランク` / `制限措置` / `臨時措置` / `特別措置` / `新株引受・権利入札`

### 重要な訂正1: 品貸料率・最高料率は「1株あたり」であり「1,000株あたり」ではない

実データ(7203、貸借値段2,985.00円、単元株数100株と仮定)で、Task 1で実装した最高料率の式と画面表示値を突き合わせて検証できた:

| 申込日 | 品貸日数 | 画面の「最高料率(品貸日数分/円)」 | 自前計算(投資単位=2985×100=298,500円→上限=100+ceil((298500-50000)/10000)×20=600円→600÷100=6.00円/株/日) |
|---|---|---|---|
| 08/13 | 1 | 6.00 | 6.00 × 1 = 6.00 ✓ |
| 08/12 | 3 | 18.00 | 6.00 × 3 = 18.00 ✓ |
| 08/07 | 2 | 12.00 | 6.00 × 2 = 12.00 ✓ |

**完全一致。** Task 1(`lambda/shared/gyakuhibu-calc.ts`)の式は「1株あたり・1日あたり」の最高料率を返しており、画面の「最高料率(品貸日数分/円)」列は`最高料率(1株/1日) × 品貸日数`(単元株数を掛ける前の値)であることが確定した。

したがって「品貸料率(品貸日数分/円)」列(実績)も同じ単位系(1株あたり、品貸日数分)のはずで、実際の逆日歩総額を出すには **`品貸料率(品貸日数分/円)の値 × 単元株数`** でよい。設計時に想定していた「1,000株あたりの日割り金額なので単元株数に換算する(÷1000×unitShares)」という前提は誤りだった。Task 6の実装(`parseTaisyakuCsv`)は `totalAmount = rate × unitShares`(1000で割らない)に修正する。

### 重要な訂正2: 「品貸料率」が空/「-」の日は「データなし」ではなく「その日は逆日歩が発生しなかった(確定0円)」

7203(トヨタ、流動性が高く逆日歩が滅多に発生しない銘柄)の観測データでは、`品貸料率(品貸日数分/円)`列がすべて `-`(空)だった一方、`最高料率(品貸日数分/円)`列は毎日値が入っていた。これは「最高料率は常に決定的に計算される上限値」「品貸料率(実績)は実際に品薄・入札が発生した日だけ値が入る」という設計時の理解を裏付ける。`-`の日をどう扱うか(0円として含めるか、`rightsHistory`から除外するか)は実装判断で変えてよいが、「取得に失敗した」わけではないことに注意。

### まだ確認できていないこと

- 実際にダウンロードしたCSVファイルの生バイト列(列名・エンコーディング・行=日付か列=日付か)。上記はすべてHTML画面表示からの推定。
- CSRFトークン・セッションCookie無しで`POST .../search`→`GET .../csv`が本当に成立するか(未ログイン・初回訪問のブラウザ相当のリクエストで実機検証が必要)。
- `kjnYmdDays`ラジオと`mkYmdFrom`/`mkYmdTo`の優先関係。

これらはTask 6実装時に「参考にしつつ、実際にLambdaからリクエストして確認しながら仕上げる」前提で進める(taisyaku.jp側の挙動が想定と違えば早期に気づけるよう、レスポンスのcontent-typeやパース失敗を明示的にログするようにする)。

## 追記(2026-10-24、信用残のtaisyaku.jp移行 Task 0: 検索結果ページの全銘柄一括CSV)

設計書`docs/superpowers/specs/2026-10-24-margin-balance-taisyaku-design.md`のTask 0として、curlで実際にリクエストして確認した。

### 確定: 基準日指定の全銘柄一括取得(方式A)が使える

1. `GET https://www.taisyaku.jp/app/stock`(`/app/stock/search`へのGETは302で`/app/stock`へ飛ぶ)でセッションCookieと`csrf_test_name`を取得
2. `POST https://www.taisyaku.jp/app/stock/search`、ボディは`csrf_test_name`と`mkYmd`(`"YYYY / MM / DD"`)だけでよい。銘柄コード等は空のまま=全銘柄。結果ページに`検索結果&nbsp;4756件`、`申込日：2026 / 10 / 22`のように出る
3. `GET https://www.taisyaku.jp/app/stock/csv`(同じCookie)→ `Content-Type: application/octet-stream`、`Content-Disposition: attachment; filename="stock_YYYYMMDDhhmmss.csv"`

Refererや特別なUser-Agentは不要だった(`Mozilla/5.0`のみで成功)。1日分につき3リクエスト。

### CSVの形式(詳細ページCSVとは別物)

- **文字コードはCP932(Shift_JIS)**。UTF-8として読むと文字化けする
- 全フィールドがダブルクォート付き。桁区切りカンマは無い
- ヘッダー(実物、14列):
  ```
  "銘柄コード","銘柄名","市場区分","貸借区分","基準日","制限措置等","融資残高（株）","貸株残高（株）","差引残高（株）","最高料率（円）","最低料率（円）","品貸料率（円）","品貸料率（年率換算/％）","応札ランク"
  ```
- **申込日の列は無い**。`基準日`は次の権利基準日(例: 2026-10-22検索で`20270331`)であり申込日ではない。行の日付は検索に使った`mkYmd`から付ける必要がある
- **同じ銘柄コードに市場区分ごとの行がある**(例: 7203は`東証`と`名証`の2行。名証行は融資残・貸株残とも0)。市場区分の内訳(2026-10-23): 東証4247 / 名証320 / 福証122 / 札証67
- `貸借区分`は`貸借`(2979) / `貸借融資`(1766) / `非貸借`(11)。CSVに載らない銘柄は制度信用の対象外
- 品貸料率列には詳細CSVと同じく`-`・`*****`が入る(残高列には今回観測されず)

例:
```
"7203","トヨタ自動車","東証","貸借","20270331","","639600","800","638800","6.20","0.00","-","-","-"
"7203","トヨタ自動車","名証","貸借","20270331","","0","0","0","6.20","0.00","-","-","-"
"3197","すかいらーくＨＤ","東証","貸借","20261231","","12900","138400","-125500","7.20","0.00","0.20","2.07","F"
```

### 値の検証

- 9418の申込日2026-08-27: 融資残1,100 / 貸株残2,039,300 / 差引-2,038,200。`2026-09-05-taisyaku-csv-balance-columns.md`の詳細ページCSVの値と完全一致
- 過去日も取得できた: 2025-10-27(4742件)、2023-10-26(4677件)。公開範囲の3年前まで遡れる

### 休日・未公表日

- 休日(2026-10-24 土曜)を指定すると`検索結果&nbsp;0件`、「ご指定の条件に該当するデータはありません。」。CSVはヘッダーのみと推定
- 未公表の当日分も同じく0件になると推定される(未検証)。営業日なのに0件の場合は「まだ公表されていない」とみなし、取得済み日付を進めない
